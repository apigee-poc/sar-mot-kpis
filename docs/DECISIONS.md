| D21 | The integration name comes from the src **file name**, so each env has its own src file (`sar-kpi-get-dev.json`, `sar-kpi-get-staging.json`). Each src file hard-codes its **own** connection (`sar-kpi-db-<env>`) and trigger. The overrides set the same values again as defence in depth. Apart from these values the two files are identical, which a unit test enforces. | 2026-11-11 (P4). `processIntegration` walks `src/` recursively, keeps only the **first** `*.json`, and calls `CreateVersion(<filename without .json>, …)`. The overrides struct has no name field, so one src file cannot produce two names. A missing overrides file is silently treated as "no overrides", and connection overrides are skipped in dry-run. So a src file that pointed at another env's connection could cross DBs. |
